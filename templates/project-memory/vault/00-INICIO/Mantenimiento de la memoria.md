# Mantenimiento de la memoria

## Cuándo revisar impacto

- Pull Request fusionado.
- Despliegue confirmado.
- Decisión aprobada.
- Cierre de una entrega o hito.
- Corrección de una contradicción comprobada.

## Flujo

1. Confirmar el evento y su evidencia.
2. Identificar únicamente las notas potencialmente afectadas.
3. Comparar cada afirmación con la fuente vigente.
4. Determinar si existe un cambio documental estable.
5. Obtener autorización cuando no exista una automatización autorizada.
6. Editar solamente las notas enumeradas.
7. Comprobar formato, enlaces, fuentes y posibles secretos.
8. Agregar rutas exactas, crear un commit descriptivo y sincronizar.

## Condiciones de parada

Detener la actualización ante conflictos, pruebas fallidas, cambios ajenos, secretos, fuentes ambiguas o un push rechazado.

Un Pull Request abierto se considera trabajo en desarrollo y no modifica la memoria vigente.
