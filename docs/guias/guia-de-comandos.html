01
Desde tu proyecto · Terminal

Abre NexaKit con npx

Entra en la carpeta de tu proyecto y ejecuta NexaKit directamente. npx obtiene el paquete de npm y abre el asistente sin una instalación global.

  • Node.js 24 o superior
  • npm con npx
  • Git, para la memoria
  • Claude Code o Codex CLI
  • Obsidian, para el paso 4

Comprueba las herramientas

Terminal · cualquier carpeta
node --version
npm --version
git --version

Comprueba también claude --version o codex --version, según el cliente que utilices, e inicia sesión en él.

Abre el asistente en tu proyecto

Terminal · sustituye la ruta por tu proyecto
cd '/ruta/a/mi-proyecto'
npx nexakit

Si npm pide descargar el paquete, confirma para continuar. Necesitas conexión para la primera descarga y una terminal interactiva. Puedes adaptar las rutas en el paso 2.

Paquete público: nexakit en npm. Abre el asistente desde la carpeta de tu aplicación. Revisa las skills y los cambios previstos antes de confirmar la instalación.

¿Cómo ejecuto memoria y las demás herramientas con npx?

El paquete tiene varios ejecutables. Para el asistente usa npx nexakit. Para otro ejecutable, indica el paquete explícitamente:

Terminal · ayuda de memoria con npx
npx --package=nexakit project-memory --help

npx conserva el paquete descargado en su caché. Los enlaces simbólicos y las recetas MCP que apuntan a esa ubicación dependen de que la caché siga disponible. Para las skills del proyecto puedes elegir copia en la revisión final. Si limpias la caché, vuelve a revisar la instalación y sus conexiones. Referencia de npm exec y npx.

Elige lo que necesita tu proyecto

Abre el asistente sobre el repositorio en el que vas a trabajar. NexaKit detectará su stack y te explicará por qué encaja cada skill.

Usando rutas de ejemplo

¿Qué agente vas a preparar?

Esta elección adapta los ejemplos de la guía. Revisa también el agente destino en la pantalla final del asistente.

Terminal · abrir el asistente
npx nexakit --project '/ruta/a/mi-proyecto' --agent all
  1. Skills para tu proyecto

    Lee el motivo, la utilidad prevista y los solapamientos. Marca las que te ayuden con tu tarea.

  2. Skills opcionales

    Añade otras solo si las necesitas. Puedes continuar sin seleccionar ninguna.

  3. Revisar e instalar

    Comprueba agentes, enlaces o copias, reglas de Git y archivos previstos. Pulsa e para editar la configuración y confirma cuando esté correcta.

↑ ↓ MoverteEspacio MarcarEnter Continuara Todas / ningunaq Salir

Compatible y recomendada significan cosas distintas. Una compatible coincide con tu stack. Una recomendada exige además escenarios funcionales pasados para cada agente destino. El catálogo actual tiene 10 skills locales con hashes comprobados y aún no tiene esos escenarios validados.

Al terminar, verás el resumen de instalación. Reinicia el agente para que cargue las skills nuevas.

Solo quiero consultar sugerencias, sin instalar
Terminal · solo lectura
npx nexakit recommend --project '/ruta/a/mi-proyecto'

Puedes concretar el perfil con --profile frontend, backend, mcp o security. NexaKit consulta el catálogo incluido; actualmente no descarga skills de un registro remoto.

Crear memoria ↓
03
Opcional · Una memoria por proyecto

Dale un lugar al contexto

La memoria guarda decisiones, arquitectura y entregas en notas Markdown. Crea una carpeta separada del código; después la abrirás en Obsidian.

Primero, revisa el plan

Terminal · vista previa, sin escribir
npx --package=nexakit project-memory init '/ruta/a/mi-proyecto-memory' --source '/ruta/a/mi-proyecto' --project-id mi-proyecto --project-name 'Mi proyecto'

Después, crea la memoria

Terminal · crea archivos en la carpeta de memoria
npx --package=nexakit project-memory init '/ruta/a/mi-proyecto-memory' --source '/ruta/a/mi-proyecto' --project-id mi-proyecto --project-name 'Mi proyecto' --apply

El proyecto fuente debe ser un repositorio Git existente. La carpeta de memoria debe estar fuera de él; tampoco puede contenerlo. Si ya tienes una memoria, ve a su diagnóstico sin volver a crearla.

Comprueba que la estructura esté bien

Terminal · diagnóstico de la memoria
npx --package=nexakit project-memory doctor '/ruta/a/mi-proyecto-memory' --strict

Resuelve los errores o advertencias del diagnóstico antes de conectar el agente.

Qué acabas de crear: notas de partida, project-memory.json y una skill específica del proyecto. La creación no configura Git, sincronización ni MCP; las notas necesitan tu contexto real.

Abrir Obsidian ↓
04
En Obsidian · Sin plugin adicional

Abre tu memoria como bóveda

Obsidian es la forma visual de recorrer y editar estas notas. La carpeta que creó NexaKit ya es tu bóveda.

  1. Abre Obsidian y entra en el gestor de bóvedas. Desde una bóveda abierta, usa el menú de la bóveda o “Abrir otra bóveda”.
  2. Selecciona “Abrir carpeta como bóveda” (Open folder as vault).
  3. Elige /ruta/a/mi-proyecto-memory, la carpeta que contiene project-memory.json y 00-INICIO.
  4. Abre 00-INICIO / Inicio del proyecto.md. Completa el propósito y revisa Estado actual y Mapa de la memoria.
/ruta/a/mi-proyecto-memory
├── project-memory.json
├── 00-INICIO/Inicio del proyecto.md
├── 01-PRODUCTO/
├── 02-ARQUITECTURA/
├── 03-IMPLEMENTACION/
├── 04-DECISIONES/
├── 05-ENTREGAS/
└── …

Abre la carpeta de memoria completa. vault/ es el nombre dentro de la plantilla del repositorio; el comando init coloca sus notas directamente en tu carpeta de destino.

Referencia: abrir una carpeta existente en Obsidian. La conexión del agente se hace en el siguiente paso.

Conectar agente ↓
05
Terminal · Conexión de memoria

Lleva el contexto a tu agente

Conecta la memoria con el cliente que elegiste en el paso 2. NexaKit enlaza su skill y registra un MCP limitado a la lectura de esa bóveda.

Revisa la conexión prevista

Terminal · memoria para Claude Code
npx --package=nexakit project-memory connect '/ruta/a/mi-proyecto-memory' --agent claude
Terminal · memoria para Codex
npx --package=nexakit project-memory connect '/ruta/a/mi-proyecto-memory' --agent codex

Aplica la conexión

Este paso cambia la configuración personal del agente. Si aparece un conflicto con una conexión o skill existente, revisa las rutas que muestra antes de continuar.

Terminal · aplicar en Claude Code
npx --package=nexakit project-memory connect '/ruta/a/mi-proyecto-memory' --agent claude --apply
Terminal · aplicar en Codex
npx --package=nexakit project-memory connect '/ruta/a/mi-proyecto-memory' --agent codex --apply

Reinicia y comprueba una lectura real

Terminal · estado de las conexiones
npx --package=nexakit project-memory status '/ruta/a/mi-proyecto-memory'

Cierra y abre una sesión nueva de tu agente. Dentro del chat, pídele:

Chat de Claude o Codex · petición de prueba
Lee mediante el MCP de memoria la nota 00-INICIO/Inicio del proyecto.md.
Resume su propósito e indica qué nota consultaste.

Comprueba que el agente realmente leyó la nota mediante MCP y que la respuesta coincide con su contenido.

Obsidian edita; el MCP consulta. Abrir Obsidian no conecta al agente. La conexión tampoco mantiene las notas actualizadas automáticamente: el código sigue siendo la fuente principal de verdad.

claude

En Codex

Terminal · abrir tu proyecto
cd '/ruta/a/mi-proyecto'
codex
Chat del agente · ejemplo de tarea
Consulta la memoria del proyecto y revisa el formulario de inicio de sesión.
Quiero mejorar su diseño sin cambiar su comportamiento.
Explica qué archivos necesitas modificar antes de empezar.
Añadir revisión cruzada entre Claude y Codex

Necesitas ambos clientes. El MCP de coordinación agent-toolkit-workflow es distinto al MCP de memoria.

Terminal · skills base, primero vista previa
npx nexakit setup --agent all
Terminal · aplicar los enlaces que falten
npx nexakit setup --agent all --apply

Ejecuta los comandos de registro MCP que imprime setup, uno para cada cliente que falte. Incluyen la ruta del paquete usado por npx. Esa ruta debe seguir existiendo; si se elimina la caché, revisa el registro y vuelve a configurar la conexión. Reinicia ambos clientes.

Terminal · comprobar instalación y permisos
npx nexakit doctor --agent all

Atiende los pendientes que indique doctor. Para Codex, revisa el acceso de su sandbox a ~/.agent-toolkit y usa la receta que imprime para tu configuración.

  1. Abre ambos agentes en la misma carpeta del proyecto.
  2. En el chat de Codex, escribe $revisar para registrar esa sesión como revisora.
  3. En el chat de Claude, escribe /programar mejora el diseño del formulario de inicio de sesión.
  4. Revisa el encargo que prepare el agente y sigue el flujo de aprobación y revisión. Consulta el estado con /estado en Claude o $estado en Codex.

También puedes intercambiar los roles. Ver el flujo de revisión cruzada.

Modelos y esfuerzo: qué se cambia y qué se sugiere

La sesión principal recomienda el nivel; no cambia automáticamente el modelo del chat abierto. Los subagentes de nivel usan el modelo y esfuerzo configurados al delegar.

Terminal · ver modelos y niveles vigentes
npx --package=nexakit agent-toolkit-inbox modelos

Para preparar los agentes de Codex, revisa npx --package=nexakit agent-toolkit-inbox agentes y aplica con el comando siguiente:

Terminal · crear agentes de nivel que falten
npx --package=nexakit agent-toolkit-inbox agentes --escribir
Dentro de Claude Code · plugin opcional de niveles
/plugin marketplace add Jcabr3ra1/nexakit
/plugin install niveles@agent-toolkit

El identificador del plugin conserva agent-toolkit por compatibilidad.

Mantener la memoria al cerrar un cambio

Después de integrar un cambio estable, pide /cerrar-memoria en Claude o $cerrar-memoria en Codex. Indica la ruta de la memoria para que pueda localizar project-memory.json.

Revisa qué notas quedaron desactualizadas y las correcciones propuestas. El MCP de lectura no escribe notas y este flujo no implica sincronización automática con Obsidian Sync o Git.

Para revisar PR fusionados pendientes en una memoria con remoto fuente configurado, usa npx --package=nexakit project-memory sync plan. Requiere GitHub CLI y acceso al repositorio. Ver la guía de sincronización.

Si algo no encaja

npx no aparece o npm devuelve E404

Si no se reconoce npx, revisa que Node.js 24 o superior y npm estén instalados y disponibles en tu PATH; abre otra terminal después de instalarlos.

Si npx nexakit devuelve E404, comprueba que el paquete ya esté publicado en el registro de npm que usas. La publicación en GitHub es independiente. No cambies el nombre del paquete para intentar continuar.

Para los ejecutables adicionales, conserva el formato npx --package=nexakit project-memory --help o npx --package=nexakit agent-toolkit-inbox modelos.

El agente no ve las skills o la memoria

Reinicia su sesión después de instalar o conectar. Comprueba npx nexakit doctor para la instalación base y npx --package=nexakit project-memory status con la ruta de la memoria para su conexión.

Usa el mismo cliente y perfil con el que configuraste MCP. Si abres Codex con un perfil, añade --perfil-codex nombre-del-perfil a npx nexakit doctor. Haz la prueba de lectura del paso 5.

init o connect informa un conflicto

Lee qué destino ya existe y comprueba a qué proyecto o instalación pertenece. Estos comandos conservan configuraciones diferentes y no las reemplazan. Una memoria ya creada se diagnostica con npx --package=nexakit project-memory doctor; no necesitas crearla otra vez.

Consultar el contrato de conexión.

No se actualizan las notas solas

Es el comportamiento previsto. NexaKit crea una estructura inicial; Obsidian permite editarla y MCP deja consultarla. Actualiza las notas al cerrar un cambio verificado. Git y Obsidian Sync se configuran por separado.

Quiero añadir más skills al catálogo

Para mantener o ampliar el catálogo desde el código fuente, añade los archivos revisados bajo catalogs/skills/, registra su origen, licencia, hashes y reglas en catalogs/skills.json, y valida el catálogo. Las pruebas funcionales son necesarias para que una skill pueda aparecer como recomendada.
