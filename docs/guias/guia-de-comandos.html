Guía de Agent Toolkit

Agent Toolkit conecta Claude Code y Codex: una terminal programa, la otra revisa y tú apruebas cada paso. Esta guía parte de cero, justo después de clonar el repositorio.

  • Programar/programar <tarea>en Claude
  • Revisar$revisaren Codex
  • Ver cómo va/estadoen cualquiera
  • Cerrar el PR/cerrar-memoriasi hay memoria

En Claude Code las skills empiezan con /. En Codex, con $. Los comandos de terminal se ejecutan desde la carpeta donde clonaste el repositorio.

Necesitas la sesión iniciada en Claude Code y en Codex. Si solo usas uno de los dos, puedes instalar y probar lo demás, pero la revisión cruzada necesita los dos.

Instalar una sola vez

  1. Clona el repositorio donde quieras

    git clone https://github.com/Jcabr3ra1/nexakit.git
cd nexakit

    Cualquier carpeta sirve. Todos los comandos siguientes se ejecutan desde ella. No la borres ni la muevas después: las skills y el servidor apuntan ahí (si la mueves, repite los pasos 4 y 5).

  2. Instala las dependencias y comprueba

    npm ci --ignore-scripts
npm test

    npm test tarda alrededor de un minuto y debe terminar sin fallos. Es opcional, pero confirma que tu Node y tu copia están bien.

  3. Revisa qué falta

    node bin/agent-toolkit.js doctor --agent all

    Comprueba Node, dependencias, Claude Code, Codex, el servidor, las skills y el permiso de Codex. Al principio es normal que marque pendientes: los resuelven los pasos siguientes.

  4. Enlaza las skills

    node bin/agent-toolkit.js setup --agent all          # vista previa, no escribe
node bin/agent-toolkit.js setup --agent all --apply  # crea los enlaces

    Enlaza las skills de esta carpeta en ~/.claude/skills (Claude) y ~/.agents/skills (Codex). Nunca reemplaza lo que ya existe: si hay un conflicto, lo indica y no toca nada.

  5. Conecta el servidor en Claude Code y en Codex

    claude mcp add --scope user --transport stdio agent-toolkit-workflow -- node "$PWD/bin/agent-toolkit-mcp.js"
codex mcp add agent-toolkit-workflow -- node "$PWD/bin/agent-toolkit-mcp.js"

    Es el servidor que guarda las revisiones entre las dos terminales. setup imprime estos mismos comandos con tu ruta. Si ya existe uno con ese nombre, no lo repitas.

  6. Deja que Codex guarde su registro de revisor

    grep -q "^\[sandbox_workspace_write\]" ~/.codex/config.toml 2>/dev/null && echo "Ya tienes la sección: añade la ruta a writable_roots a mano" || printf "\n[sandbox_workspace_write]\nwritable_roots = [\"%s/.agent-toolkit\"]\n" "$HOME" >> ~/.codex/config.toml

    Codex ejecuta sus comandos en un sandbox que solo deja escribir en el proyecto, y $revisar guarda el id de su sesión en ~/.agent-toolkit. doctor te dice si falta este permiso e imprime el comando con tus rutas.

  7. Instala el plugin de niveles (solo Claude Code)

    /plugin marketplace add Jcabr3ra1/nexakit
/plugin install niveles@agent-toolkit

    Se escribe dentro de Claude Code, no en la terminal. Añade cuatro agentes con modelo y esfuerzo fijos para delegar trabajo sin cambiar /model.

  8. Crea los agentes de nivel de Codex

    node bin/agent-toolkit-inbox.js agentes            # vista previa, no escribe
node bin/agent-toolkit-inbox.js agentes --escribir # crea los que falten

    Nunca sobrescribe ni borra. Si ya existe uno distinto lo respeta; con --escribir --forzar lo aparta como .anterior-… antes de crear el nuevo.

  9. Reinicia Claude Code y Codex y vuelve a revisar

    node bin/agent-toolkit.js doctor --agent all

    Ambos cargan el servidor y las skills al arrancar. Ahora doctor no debe mostrar pendientes: termina con código 0.

Para actualizar más adelante: git pull --ff-only y npm ci --ignore-scripts dentro del repositorio, y reinicia Claude Code y Codex.

Primer uso una terminal programa y la otra revisa

  1. Tú

    Abre dos terminales en la carpeta de tu proyecto.

    Una con claude y otra con codex. Debe ser la misma ruta en las dos, y es el proyecto en el que vas a trabajar, no Agent Toolkit.

  2. Codex

    Escribe $revisar.

    Registra su sesión y dice «Registrada; me avisarán». Termina su turno y no gasta tokens esperando. Si no encuentra su sesión, pide el id: en Codex, /status.

  3. Claude

    Escribe /programar <la tarea>.

    Claude puntúa la tarea y elige un nivel (tabla de abajo).

  4. Tú

    Confirmas el nivel, solo si es Exigente o más.

    Con Ligero o Normal, Claude sigue solo.

  5. Claude

    Programa, prueba y se revisa a sí mismo.

    Delega el código al agente del nivel cuando hace falta.

  6. Tú

    Apruebas el encargo para Codex.

    Claude te lo muestra con preguntas, archivos y criterio de aprobación. Nada se envía sin tu OK.

  7. Codex

    Revisa en solo lectura y entrega un informe.

    Claude le avisa con avisar y Codex lo recibe en su misma sesión.

  8. Claude

    Verifica cada hallazgo y corrige lo que se sostenga.

    Máximo dos rondas por cambio.

  9. Tú

    Pides el commit y el PR. Tú decides el merge.

    Si el proyecto tiene memoria de Obsidian, /cerrar-memoria la pone al día.

Si Claude es el revisor, en su terminal escribe /revisar: espera en segundo plano sin gastar tokens y se activa cuando llega el encargo.

El total sale de cinco criterios: riesgo, tamaño, ambigüedad, contexto y tipo de trabajo. Riesgo alto (seguridad, datos, dinero, producción) fija un mínimo de Exigente. Se sube de nivel solo si la corrección falló. Los nombres de Codex salen de modelos y pueden cambiar.

Comandos de terminal desde la carpeta del repositorio

Instalación agent-toolkit

  • node bin/agent-toolkit.js doctor --agent all

    Qué falta o qué está mal en la instalación. No cambia nada.

  • node bin/agent-toolkit.js setup --agent all [--apply]

    Enlaza las skills. Sin --apply es vista previa; nunca reemplaza nada.

Revisiones, modelos y consumo agent-toolkit-inbox

  • node bin/agent-toolkit-inbox.js modelos

    Qué modelos hay y la tabla de niveles vigente.

  • node bin/agent-toolkit-inbox.js rendimiento

    Qué modelo y nivel rinden mejor (hallazgos que se sostienen).

  • node bin/agent-toolkit-inbox.js consumo --project-root /ruta

    Tokens, caché y tiempo de las llamadas registradas.

  • node bin/agent-toolkit-inbox.js agentes [--escribir [--forzar]]

    Crea los agentes de nivel de Codex. Sin --escribir es vista previa.

  • node bin/agent-toolkit-inbox.js registrar --agent codex --project-root /ruta

    Guarda la sesión de Codex como revisora. Lo ejecuta $revisar; añade --thread <id> si no la encuentra.

  • node bin/agent-toolkit-inbox.js avisar --project-root /ruta --task <id> --review <id>

    Avisa a Codex de un encargo ya aprobado. Lo ejecuta la skill, no tú.

  • node bin/agent-toolkit-inbox.js cierre --project-root /ruta --task <id> --salida /ruta/traspaso.md

    Cierra una colaboración y deja un borrador de traspaso. Exige que no haya encargos activos.

Gemini (opcional, requiere agy) agent-toolkit-gemini

  • node bin/agent-toolkit-gemini.js estado

    Versión de agy y modelos disponibles.

  • node bin/agent-toolkit-gemini.js consultar --prompt "tu pregunta"

    Una explicación o respuesta directa.

  • node bin/agent-toolkit-gemini.js investigar --prompt "tu pregunta"

    Búsqueda web con resumen y fuentes.

  • node bin/agent-toolkit-gemini.js analizar --prompt "qué quieres saber" --archivo /ruta/informe.pdf

    Lee texto, imágenes, PDF o vídeo (sin audio). Hasta 8 archivos.

  • node bin/agent-toolkit-gemini.js imagen --prompt "descripción"

    Genera una imagen. Sin vídeo ni audio.

  • node bin/agent-toolkit-gemini.js historial

    Consultas anteriores. recuperar --directorio <ruta> trae un resultado sin volver a llamar al modelo.

Memoria de proyecto (opcional) project-memory

  • node bin/project-memory.js init <carpeta-nueva> --source <repositorio-del-proyecto> --project-id mi-proyecto --project-name "Mi proyecto"

    Vista previa de una memoria nueva en Obsidian para ese proyecto. --source es obligatorio. Con --apply la crea.

  • node bin/project-memory.js connect <bóveda> --agent claude

    Prepara la conexión de la memoria con Claude (o --agent codex). Con --apply la aplica.

  • node bin/project-memory.js doctor <bóveda>

    Diagnóstico de la bóveda.

  • node bin/project-memory.js sync plan <bóveda>

    Qué PR fusionados faltan por registrar en la memoria.

  • node bin/project-memory.js sync inspect <bóveda> --pr 42

    Evidencia de un PR concreto, solo lectura.

  • node bin/project-memory.js sync record <bóveda> --pr 42 --outcome documentation-updated --reviewed --summary "Producto actualizado" --note "01-PRODUCTO/Producto.md" --apply

    Registra un PR cuyas notas ya actualizaste: --note es obligatorio (repetible) con documentation-updated. Si no cambió nada, usa --outcome no-documentation-change sin resumen ni notas. Escribe solo con --apply y nunca hace commit ni push.

<bóveda> es la carpeta de memoria de un proyecto, la que contiene project-memory.json. Solo --apply escribe, y nada hace commit ni push.

Skills se escriben con / en Claude y con $ en Codex

SkillPara qué
programar <tarea>Esta terminal programa y pide revisión a la otra.
revisarEsta terminal es la revisora.
estadoTabla de las revisiones abiertas, el encargo pendiente y el último veredicto. Solo lectura.
gemini <lo que necesitas>Usa Gemini para explicar, investigar, analizar archivos o generar una imagen. investigar e imagen son atajos. Requiere agy.
cerrar-memoriaTras fusionar un PR, pone al día la memoria de Obsidian del proyecto. Solo si el proyecto tiene project-memory.json.
revision-cruzadaReúne todas las reglas de programar y revisar. Casi nunca la escribes tú.
differential-review, frontend-design, mcp-builder, web-design-guidelines, ordenar-proyectoSkills recomendadas que también instala setup: revisión de seguridad de un cambio, diseño de interfaces, crear servidores MCP, pautas web y ordenar archivos.

La memoria de Obsidian no se actualiza sola: se hace con /cerrar-memoria después de fusionar un PR.

Si algo falla

SíntomaQué hacer
Cambié algo y no se notaReinicia Claude Code y Codex.
No sé qué faltanode bin/agent-toolkit.js doctor --agent all lo dice, con el comando para arreglarlo.
node --version no empieza por v24Instala Node.js 24 (por ejemplo con nvm o Homebrew) y repite npm ci --ignore-scripts.
setup indica un conflictoYa tienes una skill con ese nombre. No la reemplaza: revisa la ruta que muestra y decide cuál conservas.
Abro Codex con --profile <nombre>Revisa con doctor --agent codex --perfil-codex <nombre>: así evalúa el permiso de ese perfil.
Moví o volví a clonar la carpetaRepite setup --apply y el registro del servidor desde la nueva carpeta.
$revisar dice «No se pudo escribir en el registro de Agent Toolkit»Es el sandbox de Codex. Haz el paso «Deja que Codex guarde su registro de revisor».
avisar dice que Codex no se registróEn Codex escribe $revisar.
registrar no encuentra la sesiónEn Codex, /status da el id. Luego registrar … --thread <id>.
Codex tarda en reaccionar al avisoSi está en mitad de un turno, el aviso espera a que termine.
Codex no reclama el encargoSu modelo no coincide con el recomendado. Cámbialo con /model.
agentes dice «ya existe y es distinto»Es lo esperado. Usa --escribir --forzar si quieres reemplazarlo; queda una copia.
sync record dice BLOCKEDAl repositorio le faltan CI o carpetas de área. Añade la fila a mano en el registro de la bóveda.
Gemini no responde o falta una imagenagent-toolkit-gemini estado comprueba agy; una imagen tardía se trae con historial y recuperar.

Límites que conviene recordar

  • El esfuerzo de un agente lo fija su archivo, pero una variable como CLAUDE_CODE_EFFORT_LEVEL puede imponerse. El modelo sí se comprobó.
  • El aviso directo a Codex se probó contra una sesión inactiva, no con un encargo real de principio a fin.
  • Los agentes de solo lectura de Codex lo son por instrucción, no por sandbox.
  • Gemini no participa en la revisión cruzada y no genera vídeo ni audio; el audio no se analiza.
  • Probado en macOS con Node 24, clonando en carpetas distintas. No se ha comprobado en Linux ni en Windows.
  • Todavía no hay una medición controlada que demuestre ahorro de tokens.
  • Nada se fusiona, se sube ni se despliega sin tu autorización.
